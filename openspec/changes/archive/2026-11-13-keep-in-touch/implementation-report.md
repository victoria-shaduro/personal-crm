# Implementation Report

## Result

Фича `keep-in-touch` реализована в ветке `keep-in-touch`. Добавлены частота общения и запланированная дата в карточке, галочка «Связались» в блоке на главной, атомарная запись заметки и следующего срока, независимый блок «Пора связаться», локальные тестовые данные и инструкция в README.md. Новые зависимости и сервисы не добавлялись. Коммит, PR и выкатка не выполнялись.

## Archive

Основная спека `openspec/specs/keep-in-touch/spec.md` создана из 16 требований; Purpose и сценарии сохранены. Макеты и снимки сохранены в архиве, ссылки основной спеки обновлены и проверены. Существующая спека `delete-contact` не менялась при синхронизации.

Архивирование выполнено с согласованным предупреждением: 19 из 20 задач завершены, задача 5.1 об уточнении старого замечания по скриншоту оставлена открытой. Строгая проверка всех основных спек прошла; активных изменений OpenSpec не осталось.

### Модель и время

- Миграция `0001_fast_rage.sql` создана через `pnpm db:generate`: два nullable-поля, индекс и CHECK. Прежние столбцы snapshot не изменены.
- `pnpm db:migrate` успешно выполнена дважды. Количество и контрольные суммы прежних полей всех контактов и заметок до и после совпали. Существующие контакты остались без расписания.
- В откатываемой транзакции CHECK отклонил шесть недопустимых сочетаний периода и даты, включая несовпадающие null и неподдерживаемые периоды.
- `pnpm exec tsx --test src/lib/keep-in-touch.test.ts`: 8 тестов пройдены. Проверены четыре периода, точное время, до/ровно/после срока, короткий месяц, високосный год, неподдерживаемые периоды и фиксированная дата Новосибирска при четырёх системных часовых поясах.

### Запись и ошибки

- Серверные действия проверены напрямую на реальной локальной базе. Временный проверочный скрипт подменял только инвалидирование Next.js и метку `server-only`; операции Drizzle выполнялись настоящими транзакциями. Проверены первое включение со старыми заметками и без, смена периода, повторное сохранение, снятие и включение, отсутствие контакта и недопустимые значения.
- Ручная заметка и «Связались» используют один момент для заметки и нового срока. Проверены последовательные заметки, отсутствие расписания, неизменность даты при пустой заметке, одновременное сохранение частоты и заметки.
- Ошибки вставки и обновления внедрялись в транзакцию: заметка и расписание полностью откатывались, успешное состояние и инвалидирование не появлялись.
- Обычное изменение телефона выполнено через интерфейс: частота и точная дата до/после совпали.
- В браузере проверены все пять вариантов частоты, сохранение после обновления и в отдельном изолированном контексте. Исправлен автоматический сброс select после действия React; выбор сохраняется и при успехе, и при ошибке.
- При имитации сетевой ошибки обе новые формы показывают сообщение рядом с действием и допускают повтор. Черновик заметки сохраняется после настройки, галочки и ошибки. Повтор после ошибки успешно сохранён.
- Галочка работает в карточке без частоты: создаётся только заметка «Связались», оба поля расписания остаются null. Проверены доступное имя, клавиатура и область 44 × 44. Двойное нажатие при задержанном запросе на главной отправило один POST и создало ровно одну заметку; дата соответствует моменту заметки плюс период.

### Блок и сквозные сценарии

- `scripts/seed-keep-in-touch.ts` добавил отдельные контакты 1014–1020. Скрипт ограничен локальной базой, только добавляет строки и не включён в обычный seed или выкатку.
- Реальная выборка сверена с SQL: все просроченные, только два будущих, порядок по дате и id, одинаковые даты, отсутствие дублей. Обе части читаются из общего снимка транзакции с одним моментом сравнения.
- В интерфейсе проверены смешанный блок, только будущие, один будущий, только просроченные и ноль расписаний. Для этого временно менялись исключительно расписания созданных агентом тестовых контактов; сохранённые значения затем восстановлены.
- Поиск без совпадений не меняет состав блока. DOM id не повторяются. Имя и дата открывают карточку; галочка оставляет текущую страницу и обновляет блок сразу.
- Ручная заметка выводит контакт из просроченных. Изменение частоты пересортировывает будущих; снятие частоты убирает контакт. Переходы назад, ссылка «Все контакты» и обновление показывают актуальные данные.
- После явного согласия владельца через интерфейс удалён только контакт 1019 «[keep-in-touch] Будущий — третий». Его отсутствие подтверждено SQL, ближайшее место занял следующий контакт. Остальные данные не удалялись.
- В локальной базе временно назначен срок через несколько секунд: при первой загрузке контакт будущий, после срока и повторной загрузки — просроченный. Точный срок в базе остался прежним. Граница ровно в срок проверена чистой функцией с управляемым временем.
- В браузерных контекстах `America/Los_Angeles` и `Pacific/Kiritimati` запланированная дата совпала, время не показано, статус просрочки совпал.
- Главная и карточка визуально сверены с приложенными макетами при 390 × 844. Длинное имя переносится, горизонтальной прокрутки нет; статусы имеют разные цвета из токенов, кнопки доступны отдельно. Снимки проверки сохранены в `/tmp/keep-in-touch-home-actual.png` и `/tmp/keep-in-touch-card-actual.png`.
- При кратковременно остановленной локальной базе показано «Не получилось загрузить данные», пустое расписание не показано. База сразу запущена обратно.

## Environment

Первоначальный запуск Turbopack в ограниченном окружении упирался в FSEvent; Webpack с опросом файлов позволил проверить запись, но не собирал стили через настроенный в проекте загрузчик Turbopack. Для визуальной проверки и финальной сборки использован обычный Turbopack вне ограниченного окружения. Первоначальные ошибки сгенерированных типов маршрутов больше не воспроизводятся. В процессе проверки исправлено имя параметра read-only транзакции Drizzle, после чего проверка типов и сборка прошли.

После повторной приёмки в локальной базе оставлена свежая демонстрационная семёрка 1021–1027 с обычными именами и пометкой о тестовых данных в описании. Созданные агентом прежние контакты с изменёнными во время проверок расписаниями удалены с согласия владельца. Эти локальные данные не переносятся на сервер.
